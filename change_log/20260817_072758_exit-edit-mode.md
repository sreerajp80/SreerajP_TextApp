# Change log — A clear way to quit edit mode, and auto-save gaps

Implements [plans/20260817_064945_exit-edit-mode.md](../plans/20260817_064945_exit-edit-mode.md).

## Why

Once a tab went into edit mode there was no clear way out. The only exit was a
toolbar toggle that showed an **eye** while editing, which reads as "preview",
not "stop editing". Saving did not leave edit mode, and the Android back button
did nothing — there was no `PopScope` anywhere in the app.

While checking this, auto-save was reviewed too. It works (all five formats wire
it up, and its tests pass), but three real gaps were found and fixed.

## What changed

### A. The toolbar button now names the way out

In the TXT, Markdown, JSON and XML toolbars, the edit toggle shows
`Icons.edit_off_outlined` with the tooltip **"Exit edit mode"** while editing.
Before it was an eye (TXT, Markdown) or a filled pencil (JSON, XML) — both of
which still read as "edit".

### B. Android back leaves edit mode, asking about unsaved work first

New `_EditModeBackGuard` in `tabs_workspace.dart` wraps the workspace in a
`PopScope`:

- Not editing → back behaves exactly as before.
- Editing, no unsaved edits → leave edit mode, no dialog.
- Editing with unsaved edits → the **existing** unsaved-changes dialog, the same
  one the tab-close guard uses:
  - **Save** / **Save as a copy** → save, then leave edit mode. A failed save
    keeps the user in edit mode and shows the reason; a read-only file falls
    back to a copy, as closing already did.
  - **Discard** → `reloadFromDisk()` puts the file's own content back and the
    crash-recovery draft is dropped, so the draft banner cannot offer the
    thrown-away text later. Then leave edit mode.
  - **Keep editing** → nothing changes.

The guard listens to the active document's session, so `canPop` is right from
the moment the mode changes. It skips oversized files, which open in the
degraded read-only view and must never build a heavy session (Phase 10.2).

### C. A finished save goes back to view mode

New editor setting **"Leave edit mode after saving"**, default **on**, in
Settings › Editor. The four direct-save helpers now return `bool` (was `void`)
so the toolbar knows whether the file was actually written; a cancelled or
failed save never moves the user.

### D. One place that knows "is this tab editing?"

`format_dispatch.dart` gained `isTabEditing`, `exitTabEditMode`,
`exitEditModeAfterSave` and `tabSessionListenable`. Each maps the four different
mode enums (`TabViewMode`, `MdMode`, `JsonViewMode`, `XmlViewMode`) onto the one
question the shell asks, so the back guard and the toolbars do not each repeat
it. `isTabEditing` and `exitTabEditMode` use `peek`, so they never build a
session that does not exist.

**Not done (decided during review):** tapping a file on Home that is already
being edited keeps the tab in edit mode, exactly as the user left it.
`open_file_action.dart` is unchanged.

### E. Auto-save fixes

- **E1 — the draft is now flushed when the app leaves the foreground.** The
  editor surfaces already saved the *reading position* on pause but not the
  draft, so an OS kill lost everything typed since the last tick (up to 600 s
  with the slowest setting). New `flushDraft()` on all five sessions, called
  from the same lifecycle hook. CSV had no lifecycle observer at all; it now has
  one on its document view, which also fixes its reading position.
- **E2 — a failed auto-save is no longer dropped.** `Timer.periodic` threw the
  tick's future away, so a failed draft write became an unhandled async error
  nobody saw while the user kept typing. `AutoSaver.tick` now catches, records
  the failure, retries the same content next tick, and the new
  `AutoSaveFailingBanner` warns the user in every format's document view.
- **E3 — changing the interval now reaches open tabs.** The interval was read
  once when a session was built. The session managers now watch
  `editorSettingsProvider` and push changes into live sessions via
  `setAutoSaveInterval`.

Deliberately unchanged: `dispose()` still stops the timer without a last tick.
The retention policy never releases a dirty tab, a real close already goes
through the save prompt, and a flush there would fight the "Discard" choice.

## Files changed

**Core**
- `lib/core/editor/draft_store.dart` — `AutoSaver` failure handling
- `lib/core/editor/auto_save_failing_banner.dart` — new shared warning banner
- `lib/core/editor/editor_settings.dart`, `editor_settings_controller.dart` —
  `exitEditAfterSave`

**Formats** (txt, markdown, json, csv, xml)
- `*_document_session.dart` — `flushDraft`, `setAutoSaveInterval`,
  `autoSaveFailing`; the interval field became mutable
- `*_session_manager.dart` — `applyAutoSaveInterval` + watch the settings
- `*_document_view.dart` — show the auto-save warning banner (CSV also gained
  the lifecycle observer)
- `*_editor_surface.dart` (txt, md, json, xml) — flush the draft on pause
- `*_toolbar.dart` (txt, md, json, xml) — exit icon and label; leave edit mode
  after a save
- `*_save_options_sheet.dart` (txt, md, json, xml) — direct save returns `bool`
- `format_dispatch.dart` — the shared edit-mode helpers

**Shell**
- `lib/shell/tabs/tabs_workspace.dart` — `_EditModeBackGuard`; `_CloseSaver`
  became `_TabSaver` with revert + draft discard
- `lib/shell/settings/sections/editor_section.dart` — the new switch

**Localization**
- `lib/l10n/app_en.arb`, `app_ml.arb` — `editorExitEditMode`,
  `editorAutoSaveFailing`, `editorExitEditAfterSave`,
  `editorExitEditAfterSaveSub` (generated files regenerated with
  `flutter gen-l10n`)

**Tests**
- `test/shell/exit_edit_mode_widget_test.dart` — new, 10 tests: the exit label,
  back leaving edit mode, the clean and dirty paths, Keep editing, Discard, back
  when not editing, and the three leave-after-save cases
- `test/formats/txt/txt_autosave_test.dart` — new, 6 tests for `flushDraft` and
  `setAutoSaveInterval`
- `test/core/editor/draft_store_test.dart` — 2 tests for the failure path
- `test/core/editor/editor_settings_test.dart` — the new setting
- `test/support/test_support.dart` — `FakeSafService` now overrides
  `isWritable`; without it the real one waits on a platform channel that never
  answers in tests, which hung any document load
