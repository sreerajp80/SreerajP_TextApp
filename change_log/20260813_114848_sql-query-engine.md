# Change log — Embedded Local SQL Query Engine for CSV & JSON (Feature 4)

Implements `plans/20260813_112404_sql-query-engine.md`.

---

## What was added

Read-only SQL over an open CSV file or JSON array, fully offline. It is reached
from the overflow menu of both the CSV and the JSON format.

The open document is copied into a **throwaway in-memory SQLite database** that
is created when the screen opens and closed when it leaves. The app's own
database is never touched and no file is written.

### No new dependency

The plan called this out and it held. The roadmap suggested
`sqflite_common_ffi`, but that package is a **desktop and test-host** factory and
was already in the project only as a `dev_dependency`. On Android the plain
`sqflite` package the app already ships opens an in-memory database with
`inMemoryDatabasePath`, which is a real SQLite engine. `sqflite_common_ffi` is
injected **only by the tests**, which is how the engine runs on the host with no
device.

`core/sql`. They were moved to the formats layer instead, because `core/sql`
importing `formats/csv` would have run against the dependency direction in
`CLAUDE.md` §4. `core/sql` now knows only about `SqlSource`, and the toolbars
supply the adapters. For the same reason the number and currency reading is
implemented inside `sql_dataset.dart` rather than reused from
`formats/csv/csv_types.dart`; the duplication is small and the comment says why.

`sql_query_screen_test.dart` was **not** in the plan. It was added because the
screen has a real failure mode a unit test cannot see (see "Bug found and fixed"
below). It drives the engine inside `WidgetTester.runAsync`, since SQLite needs
the real event loop. To make it possible, `SqlQueryScreen` gained a
`@visibleForTesting databaseFactoryOverride` argument; the app leaves it null.

## Design decisions worth recording

- **Columns are typed from their own values**, so `WHERE amount > 100` compares
  numerically. All-numeric (including `1,234` and `$1,299.00`) → `REAL`,
  `true`/`false`/`yes`/`no` → `INTEGER`, everything else → `TEXT`. **Dates stay
  text on purpose**: an ISO date already compares in order as text, and
  `31/01/2026` has no single right numeric reading.
- **A blank cell is `NULL`**, never `0` or `''`, so `AVG` and `COUNT` do not
  count empty cells.
- **Blank and repeated headers are repaired** (`column_2`, `total_2`), keeping
  each header's own spelling, and the schema panel says what was renamed. A
  header containing a quote is quoted correctly rather than breaking the schema.
- **The guard exists for `ATTACH`.** The copy is throwaway, so a write could not
  damage the user's file — but `ATTACH` would let a query open the app's real
  `text_data.db` on disk. String literals and comments are masked before the
  check, so `WHERE note = 'delete me'` still runs. `replace()` is deliberately
  **not** blocked: it is a normal string function, and `REPLACE INTO` cannot
  appear in a statement that must start with `SELECT` or `WITH`.
- **The result cap is applied by wrapping** the user's statement in
  `SELECT * FROM (…) LIMIT n+1`; the extra row is what detects truncation.
- **`singleInstance: false`** on the in-memory open. Without it, a reload would
  be handed back the database the screen had just closed — the "a fresh load does
  not see the previous tables" test guards this.
- **The whole CSV is loaded, not the filtered grid.** A query that silently saw
  only part of the file would be misleading; SQL is the real filter.

## Bug found and fixed during the work

The screen originally started its load in `initState`. That path reads localized
strings, and looking up an inherited widget during `initState` is not allowed in
Flutter. The load now starts in a post-frame callback. The widget test was added
because a unit test could never have caught this.

## Stated limits (all shown in the UI)

- **200,000 rows** loaded per table; the schema panel says when the cap bites.
- **5,000 result rows** shown; the summary bar says when the result was cut.
- **No mid-query cancel.** SQLite runs on sqflite's background thread and cannot
  be interrupted part-way, so the row cap is the honest protection.
- **A snapshot, not the live buffer.** Editing the document afterwards changes
  nothing until "Reload data" is tapped.
- **Nested JSON is not flattened**: a nested object keeps the table view's short
  text (`{ 3 }`), so a query can select it but not look inside it.
- **The result cannot be opened as a new in-app tab.** Every tab assumes a real
  SAF URI — the same architectural limit already recorded for memory-only notes.
  The result can be copied as CSV or saved as a new CSV file through the user's
  own picker.

## Outstanding

**A run on real Android hardware has not been checked by hand.** The tests drive
SQLite on the host through the FFI factory; they cannot prove the device's own
SQLite build behaves identically, or that a 200,000-row copy is comfortable on a
small phone. This must be done before release (`CLAUDE.md` §10), the same rule
already applied to LAN sync and AirQR.
