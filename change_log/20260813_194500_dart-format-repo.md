# Change log — run `dart format` across our own Dart code

**Date:** 2026-08-13
**Plan:** [plans/20260813_193000_dart-format-repo.md](../plans/20260813_193000_dart-format-repo.md)

## What was wrong

Our Dart code was not formatter-clean. Dart 3.7 shipped a new formatter style (the "tall
style") that changes how long argument lists, constructor calls, and chained calls wrap.
The codebase was written under the old style, so nearly every file with a multi-line call
differed.

## What was changed

1. Ran `dart format lib/ test/` → **269 files reformatted**.
2. That surfaced **10 new analyzer issues** (see below), fixed with
   `dart fix --apply --code=curly_braces_in_flow_control_structures` → **10 fixes in 5 files**.
3. Ran `dart format lib/ test/` again to settle the layout after the braces were added.

Final diff versus the last commit: **271 files changed, 4666 insertions, 3308 deletions.**
(That is the 269 formatted files plus 2 files touched only by the earlier
`prefer_initializing_formals` change.)

## The one thing that did not go as planned

The plan predicted analyze would stay at 0 issues after formatting. **It did not — it went
to 10.**

Cause: lines like

```dart
if (source.isEmpty) return const FormulaResult.failure('The formula is empty.');
```

were over 80 columns, so the formatter split them onto two lines. The
`curly_braces_in_flow_control_structures` lint allows a braceless single statement **only
when it sits on the same line as the `if`**. Once split, the lint fires.

Fix: add the braces, which is what the lint wanted anyway.

```dart
// after
if (source.isEmpty) {
  return const FormulaResult.failure('The formula is empty.');
}
```

Affected files: `lib/core/editor/encoding.dart` (1),
`lib/formats/csv/csv_document_session.dart` (1), `lib/formats/csv/csv_formula.dart` (3),
`lib/formats/csv/csv_table.dart` (1), `lib/formats/json/json_path.dart` (4).

This is the only part of the change that is not pure whitespace. Adding braces around a
single statement does not change behaviour.

## Checks run

- `dart format lib/ test/` re-run → **0 files changed**. The formatting is now a stable
  fixed point, so it will not keep churning.
- `flutter analyze` → **No issues found!**
- `flutter test` → **all 831 tests passed** (run both before and after the brace fix).
- Spot-checked `lib/sync/sync_crypto.dart`, `lib/sync/sync_transport.dart` and
  `lib/core/storage/key_value_store.dart`. Only line breaks moved — for example a
  three-line `raw.toUpperCase().replaceAll(...)` chain was rejoined onto one line. No
  change to crypto, key derivation, or what is stored or sent. The suite covers this
  directly (wrong-code rejection, GCM tag failure, PBKDF2 determinism) and passes.

## What was deliberately NOT formatted

**`third_party/`** — the vendored `re_editor` source, confirmed untouched
(`git status third_party/` is empty). Plain `dart format .` would have rewritten 323 files
because it sweeps that folder. It is other people's code, it is already excluded from
analysis in `analysis_options.yaml`, and reformatting it would make future updates from
upstream painful to merge.

No `formatter:` / `page_width` setting was added to `pubspec.yaml`. The formatter uses its
default 80-column width.

## Note for whoever reads git history

This is a large whitespace commit. `git blame` on these lines will point here rather than
at the real author. `git blame -w` still works, and this commit can be added to a
`.git-blame-ignore-revs` file to make blame skip it permanently. Any in-flight branch or
stash will likely conflict when merged.
