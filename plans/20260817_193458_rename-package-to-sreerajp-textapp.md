# Rename Dart package from `text_data` to `sreerajp_textapp`

**Status:** completed

## The issue

`pubspec.yaml` line 1 was changed from `name: text_data` to `name: sreerajp_textapp`.
The rest of the project was not updated. Every Dart file still imports app code as
`package:text_data/...`, which is now a package that does not exist.

Result: `flutter analyze` reports **11,651 issues**. Almost all of them are cascade
errors — each broken import makes every class and function it provided look undefined.

Counts today:

| Where | `package:text_data/` occurrences |
|-------|------|
| `lib/` and `test/` Dart files | 1,924 across 437 files |
| Docs (`CLAUDE.md`, `AGENTS.md`) | 2 |
| `test/analysis_options.yaml` (comment only) | 1 |

The code itself is fine. This is a pure naming mismatch.

## The decision

Keep the new name `sreerajp_textapp` and rewrite every import to match.

## Files to be changed

1. **All `.dart` files under `lib/`** (about 300 files) — replace the literal string
   `package:text_data/` with `package:sreerajp_textapp/`.
2. **All `.dart` files under `test/`** (about 135 files) — same replacement.
3. **`CLAUDE.md`** §9 — the line
   ``- Use `package:text_data/...` imports, **not** relative imports.``
   becomes `package:sreerajp_textapp/...`.
4. **`AGENTS.md`** — the same line, kept in step with `CLAUDE.md`.
5. **`test/analysis_options.yaml`** — the header comment mentions
   `package:text_data/...`; update the text. No rule changes.

Nothing else. `pubspec.yaml` is already correct and will not be touched (its version
bump to `1.9.0+21` is a separate, intentional change and stays as it is).

## What will deliberately NOT change

- **`plans/` and `change_log/` history files.** These are a written record of what was
  done at the time. Rewriting them would falsify the record.
- **`text_data.db`** — the app's SQLite file name (`AppDatabase.defaultFileName`).
  This is a file on the user's device. Renaming it would make every existing install
  lose its recents, favourites, bookmarks and drafts index. It has nothing to do with
  the Dart package name.
- **`in.zohomail.sreerajp.text_data/saf`** — a Kotlin `MethodChannel` name string in
  `android/app/src/main/kotlin/in/sreerajp/textapp/SafChannel.kt`. Channel names are
  free-form strings shared between Dart and Kotlin; they are unrelated to the package
  name and changing one side alone would break the SAF bridge.
- **Android application id** `in.sreerajp.TextAPP` — unrelated to the Dart package
  name, and changing it would break app updates and signing.
- **Generated l10n files** (`lib/l10n/app_localizations*.dart`) are regenerated by the
  build, but they contain no `package:text_data/` import, so no special handling is
  needed.

## Plan for the fix

1. Run a scripted, exact-string replacement of `package:text_data/` with
   `package:sreerajp_textapp/` across `lib/**/*.dart` and `test/**/*.dart` only.
   The search string is unambiguous, so there is no risk of hitting unrelated text
   such as `text_data.db`.
2. Update the three prose references by hand (`CLAUDE.md`, `AGENTS.md`,
   `test/analysis_options.yaml`).
3. `flutter pub get` — regenerate `.dart_tool/package_config.json` under the new name.
4. `dart format lib test`.
5. `flutter analyze` — must reach **zero** issues (CLAUDE.md §9).
6. `flutter test` — must pass, to prove nothing beyond imports moved.

## Risk

Low. The change is mechanical and the replaced string appears nowhere except in
import and export directives. If anything goes wrong the whole change can be undone
with `git checkout -- lib test`.

## Verification

- `flutter analyze` reports zero issues (down from 11,651).
- `flutter test` passes with the same results as before the change.
- No remaining `package:text_data/` matches under `lib/` or `test/`.
