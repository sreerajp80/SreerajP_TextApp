# Upgrade the project to Flutter 3.44.8 / Dart 3.12.2

**Status:** completed

## What the issue is

The installed toolchain is now:

```
Flutter 3.44.8 • channel stable
Tools • Dart 3.12.2 • DevTools 2.57.0
```

But the project still declares the old minimums, **Flutter 3.41.9 / Dart 3.11.5**, in
`pubspec.yaml` and in the docs. So the written rules do not match the tools we build with.

## The plan

Raise the declared minimum toolchain to **Flutter 3.44.8 / Dart 3.12.2** everywhere the
project states its own stack, then re-resolve packages and re-run the checks.

### 1. Code / config

- `pubspec.yaml`
  - `environment.sdk`: `^3.11.5` → `^3.12.2`
  - `environment.flutter`: `">=3.41.9"` → `">=3.44.8"`

### 2. Project docs (the "our stack is X" statements)

- `CLAUDE.md` §2 — Flutter 3.41.9 / Dart 3.11.5 → 3.44.8 / 3.12.2
- `README.md` line 31 — same bump
- `docs/TextData-Idea.md` lines 11–12 — same bump
- `docs/features.md` line 289 (Framework & Engine row) — same bump
- `docs/implementation-plan.md` line 104 — same bump

### 3. Re-resolve and verify

- `flutter pub get` (this also rewrites the `pubspec.lock` SDK constraints block).
- `flutter analyze`
- `flutter test`

### 4. Change log

Write `change_log/<timestamp>_upgrade-flutter-3-44-8.md` when done.

## What will NOT be changed

- **`docs/guidelines/**`** — these are general Flutter standard documents that say
  "Reflects Flutter 3.41 / Dart 3.11". They are reference material, not this app's stack
  statement. Re-dating them is a separate, bigger job.
- **`plans/` and `change_log/` history** — old files record what was true at the time.
  History should not be rewritten.
- **`third_party/re_editor`** — no change needed. The vendored copy is 0.10.0, and the
  upstream "Fix the compile error in Flutter 3.44.0" landed in 0.9.0, so it is already in.
  The local `enableSuggestions: false` patch stays as is.
- **Package versions in `dependencies`** — this plan only moves the SDK floor. Bumping
  packages is a separate change.

## Risks

- A new SDK can bring new analyzer lints or deprecations. If `flutter analyze` or
  `flutter test` reports problems after the bump, I will list them and ask before fixing,
  because those fixes are outside this plan's scope.
